# ربات تلگرام سفارشی

سیستم آپلود/لینک‌دهی فایلِ نسخهٔ اولیه حذف شده است. امکانات فعلی:

- جوین اجباری با متن ثابت و دکمه‌های اینلاین عضویت/بررسی
- پایش رویداد خروج از کانال/گروه اجباری؛ برای عضوی که قبلاً عضویتش در ربات تأیید شده، اعلان لغو اشتراک و نام همان کانال/گروه بلافاصله و بدون نیاز به `/start` یا زدن دکمه ارسال می‌شود. کاربر تازه‌ای که هنوز عضویتش را در ربات تأیید نکرده، فقط راهنمای جوین را می‌بیند و پیام لغو اشتراک نمی‌گیرد.
- پیام شروع چندبخشی و دکمه‌های سفارشی اعضا در منوی پایین چت (Reply Keyboard)
- ارسال همگانی چندپیامه با تأیید نهایی؛ اگر ارسال راهنمای جوین به یک کاربر مسدود/غیرفعال خطا بدهد، پردازش اعضای بعدی ادامه می‌یابد و کاربر غیرقابل‌دسترسی از فهرست حذف می‌شود
- بکاپ JSON به پیوی مالک هنگام راه‌اندازی و هر 24 ساعت؛ مالک می‌تواند در پیوی ربات دستور `/backup` (یا `/backup_now`) را برای بکاپ فوری بفرستد؛ `/backup` در منوی فرمان‌های مالک هم ثبت می‌شود. ارسال فایل JSON به پیوی ربات، فقط توسط مالک، تنظیمات و دکمه‌ها و فهرست اعضا را بازیابی می‌کند

## راه‌اندازی و امنیت

مقادیر محرمانه در فایل خصوصی `.env` نگهداری می‌شوند. اجرای مستقیم `main.py` یا `bot_app.py` این فایل را می‌خواند. `.env` در ZIP و Docker image قرار نمی‌گیرد؛ برای Docker، مقادیر را در Environment Variables هاست تنظیم کنید. فایل‌های `env.example` و `config.example.json` نمونه‌اند.

مالک باید یک‌بار `/start` بزند تا ربات بتواند بکاپ را در پیوی او بفرستد. برای دریافت رویداد فوری خروج، ربات باید در هر کانال/گروه اجباری ادمین باشد. مدیران ربات هم از شرط عضویت و اعلان لغو اشتراک مستثنا نیستند؛ همهٔ مسیرهای ارسال محتوای اعضا عضویت را دوباره بررسی می‌کنند. پس از Deploy نسخهٔ جدید، هنگام آزمایش خروج در لاگ باید خط `Chat-member update` با `required_chat=True` دیده شود؛ اگر رویداد نمی‌رسد یا مقدار `required_chat=False` است، دسترسی ادمین ربات و شناسه/نام کانال اجباری را بررسی کنید. برای ماندگاری داده‌ها پس از Deploy مجدد، Volume پایدار را روی `/app/data` متصل کنید. توکن و کلیدهای API را در Git یا بسته‌های قابل‌اشتراک قرار ندهید.
